# Лабораторная работа № 4 — взаимодействие процессов и потоков

Вариант 6. Модель «Обедающие философы»: справедливое распределение ресурсов.
Реализация для Ubuntu/Linux на C++17 с использованием POSIX-эквивалентов
механизмов синхронизации Windows API.

## Индивидуальные параметры

- `STUDENT_ID = 028`
- `SEED = 1000 + 28 * 97 = 3716`
- `OPERATIONS = 100 + 28 * 5 = 240` циклов на философа
- Стандартная конфигурация: 5 философов по 100 циклов
- Индивидуальная конфигурация: 5 философов по 240 циклов

## Что моделируется

За круглым столом сидят `N` философов. Между соседними философами лежит одна
вилка, всего `N` вилок. Для приёма пищи философу нужны обе соседние вилки.
Каждый философ выполняет заданное число циклов:

```text
THINKING -> WAITING -> EATING -> THINKING
```

Запрос на обе вилки является атомарным: философ не может удерживать одну вилку
и ждать вторую. Запросы ставятся в центральную очередь. В режиме `fifo`
обслуживается только первый запрос очереди; если его невозможно удовлетворить,
более поздние запросы его не обходят. В режиме `scan` разрешён обход
заблокированного запроса, что позволяет исследовать несправедливость и
голодание.

## Среда и соответствие Windows API

Проект выполняется в Linux, поэтому используются функциональные аналоги
механизмов Windows API. Это же решение уже применялось в лабораторной работе
№ 3.

| Механизм Windows | Реализация в Linux/POSIX |
|---|---|
| `CRITICAL_SECTION` | `std::mutex` / `pthread_mutex_t` |
| `CreateEvent` (auto-reset) | `sem_init()` |
| `SetEvent` | `sem_post()` |
| `WaitForSingleObject` | `sem_timedwait()` |
| `GetCurrentThreadId` | `gettid()` |
| `Sleep` | `std::this_thread::sleep_for()` |
| `InterlockedIncrement` | `std::atomic` |

`Sleep`/`sleep_for` используется только для имитации времени обдумывания и еды,
а не для согласования доступа к вилкам.

## Архитектура

- `N` потоков-философов.
- Одна общая очередь заявок.
- Массив владельцев вилок `fork_owner[N]`.
- Один мьютекс (`critical section`) защищает очередь, владельцев вилок,
  состояния и статистику.
- Для каждой заявки создаётся отдельный auto-reset event, на котором философ
  ожидает решения с тайм-аутом.
- Решение о выдаче вилок принимается в `dispatch_locked()` под защитой
  мьютекса. Функция вызывается при постановке заявки и при освобождении вилок.
- Отдельный поток-арбитр не требуется: очередь централизована, а все решения
  сериализуются критической секцией.

Подробное описание архитектуры и алгоритмов находится в
[`docs/architecture.md`](docs/architecture.md).

## Параметры запуска

Параметры должны задаваться без изменения исходного кода:

```text
--philosophers N       количество философов (по умолчанию 5)
--cycles C             количество циклов на философа
--student-id 28        студенческий идентификатор
--seed 3716            зерно генератора задержек
--mode fifo|scan       режим обслуживания очереди
--think-min-ms         минимальное время обдумывания
--think-max-ms         максимальное время обдумывания
--eat-min-ms           минимальное время еды
--eat-max-ms           максимальное время еды
--timeout-ms           тайм-аут ожидания вилок
--max-duration-ms      максимальная длительность эксперимента
--log-file PATH        файл журнала событий
--wait-csv PATH        CSV с временами ожидания заявок
--verbose              подробный вывод событий
--quiet                только итоговая сводка
```

## Сборка и запуск

```bash
cmake -S lab04-sync -B lab04-sync/build -DCMAKE_BUILD_TYPE=Release
cmake --build lab04-sync/build -j
./lab04-sync/build/lab04_sync --philosophers 5 --cycles 100 --mode fifo
```

Проверка корректности:

```bash
ctest --test-dir lab04-sync/build --output-on-failure
```

Индивидуальный запуск:

```bash
./lab04-sync/build/lab04_sync \
  --philosophers 5 \
  --cycles 240 \
  --seed 3716 \
  --mode fifo \
  --log-file lab04-sync/data/individual_fifo.log
```

## Проверяемые инварианты

1. Одна вилка не может одновременно принадлежать двум философам.
2. Философ в состоянии `EATING` владеет обеими своими вилками.
3. Количество занятых вилок равно `2 * количество едящих философов`.
4. В очереди не больше `N` заявок и нет дубликатов заявок одного философа.
5. В режиме `fifo` отсутствуют обходы ожидающих заявок (`overtakes == 0`).
6. После завершения очередь пуста, все вилки свободны, все философы
   находятся в состоянии `FINISHED`, все циклы выполнены.

Число нарушений инвариантов выводится в итоговой сводке. Корректный запуск
должен завершаться с `INVARIANT_VIOLATIONS=0`.

## Эксперименты

- Конфигурация A: 5 философов, 100 циклов, `fifo` — стандартная.
- Конфигурация B: 5 философов, 240 циклов, `fifo` — индивидуальная.
- Конфигурация C: 5 философов, 240 циклов, `scan` — сравнение с FIFO.
- Конфигурация D: 3, 5 и 7 философов, 240 циклов, `fifo` — влияние нагрузки.

Для каждой конфигурации выполняется по три запуска. Подробное описание
конфигураций, сырые данные и результаты находятся в
[`data/README.md`](data/README.md). Запуск и построение графиков:

```bash
python3 lab04-sync/scripts/run_experiments.py
python3 lab04-sync/scripts/plot_results.py
```

Графики сохраняются в `data/plots/`:

1. пропускная способность FIFO при разном числе философов;
2. распределение времени ожидания по философам для FIFO и SCAN;
3. среднее и максимальное время ожидания для FIFO и SCAN.
