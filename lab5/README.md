# Лабораторная работа № 5 — элементы сетевого программирования

Вариант 6. **Децентрализованный TCP-чат**.

Реализация для Ubuntu/Linux на C++17 с использованием POSIX-сокетов —
функциональных аналогов Windows Sockets API.

## Индивидуальные параметры

- `STUDENT_ID = 028`
- `SEED = 1000 + 28 * 97 = 3716`
- `BASE_PORT = 20000 + 28 = 20028`
- Транспортный протокол: TCP
- Минимальное число равноправных узлов: 3
- Максимальный размер полезной нагрузки одного сообщения: 65536 байт
- Рекомендуемый TTL: 3–5

## Назначение приложения

Каждый узел `peer_chat` одновременно:

- принимает входящие TCP-соединения;
- устанавливает исходящие TCP-соединения с узлами из `--peer`;
- отправляет сообщения по команде пользователя или в автоматическом режиме;
- принимает сообщения и пересылает их дальше, если адресат — другой узел;
- уменьшает TTL при пересылке и не пересылает сообщение повторно, если его
  `messageId` уже встречался.

Центральный сервер не используется: все узлы равноправны. Цепочка
`A -> B -> C -> D` образуется тем, что каждый узел подключается к следующему
через параметр `--peer`.

## Запуск цепочки из трёх узлов

Терминал 1 — узел C:

```bash
./build/peer_chat --id C --port 20030 --run-ms 60000 \
  --log-file logs/C.log
```

Терминал 2 — узел B, подключённый к C:

```bash
./build/peer_chat --id B --port 20029 --peer 127.0.0.1:20030 \
  --run-ms 60000 --log-file logs/B.log
```

Терминал 3 — узел A, подключённый к B:

```bash
./build/peer_chat --id A --port 20028 --peer 127.0.0.1:20029 \
  --run-ms 60000 --log-file logs/A.log
```

В терминале A ввести:

```text
msg C привет
```

Узел A отправит сообщение узлу B, B перешлёт его узлу C. В журнале C появится
событие `DELIVER`, в журнале B — `FORWARD`.

## Автоматическая отправка

```bash
./build/peer_chat \
  --id A --port 20028 --peer 127.0.0.1:20029 \
  --messages 20 --dest C --text payload --ttl 5 \
  --send-interval-ms 50 --run-ms 1500 \
  --log-file logs/A.log --stats-file logs/A.stats
```

Параметры:

- `--id` — идентификатор участника;
- `--host` — адрес прослушивания, по умолчанию `127.0.0.1`;
- `--port` — порт прослушивания, 20000–29999;
- `--peer host:port` — узел, к которому нужно подключиться (можно повторять);
- `--ttl` — начальный TTL исходящих сообщений;
- `--messages` — количество автоматически отправляемых сообщений;
- `--dest` — идентификатор адресата;
- `--text` — текст сообщения;
- `--send-interval-ms` — интервал между сообщениями;
- `--run-ms` — время работы после отправки (для интерактивного режима —
  максимальное время работы);
- `--expect-messages` — досрочно прекратить ожидание после N доставленных
  сообщений;
- `--timeout-ms` — тайм-аут подключения и отправки;
- `--log-file` — файл журнала;
- `--stats-file` — файл с итоговыми счётчиками;
- `--quiet` — не дублировать журнал в стандартный вывод.

Интерактивные команды: `msg <dest> <text>`, `stats`, `help`, `quit`.

## Протокол прикладного уровня

TCP-сообщение кодируется как:

```text
[Length: 4 байта, big-endian][Payload: Length байт]
```

Payload — текст UTF-8 из строк `key=value`, разделённых `\n`. Значения
экранируются (`\\`, `\n`, `\r`).

Типы сообщений:

| Тип | Отправитель | Получатель | Содержимое | Реакция |
|---|---|---|---|---|
| `HELLO` | любой узел | любой узел | `id` | запоминание идентификатора соединения |
| `CHAT` | любой узел | любой узел | `msgid`, `dest`, `ttl`, `text`, `sent_us` | доставка, пересылка, `DROP_TTL`, `NO_ROUTE` |
| `ERROR` | любой узел | любой узел | `code`, `text` | запись в журнал |

Подробное описание — в [`docs/protocol.md`](docs/protocol.md).

## Обработка ошибок

Реализованы:

- невозможность создания сокета и занятый порт (`LISTEN_ERROR`);
- отказ соединения и недоступный сервер (`CONNECT_FAIL`, повторные попытки);
- закрытие соединения (`PEER_CLOSED`, `DISCONNECTED`);
- тайм-аут подключения и отправки (`connect timeout`, `send timeout`);
- ошибки приёма (`RECV_ERROR`, `SEND_ERROR`);
- некорректное сообщение (`PROTOCOL_ERROR`, ответ `ERROR`);
- неизвестный тип сообщения;
- превышение размера сообщения;
- дубликаты (`DUP`);
- исчерпание TTL (`DROP_TTL`);
- отсутствие маршрута (`NO_ROUTE`).

Ошибки сокетов выводятся с функцией, кодом `errno` и текстом `strerror(errno)`
— аналог `WSAGetLastError()`.

## Тестирование

```bash
ctest --test-dir build --output-on-failure
```

Тесты проверяют:

1. доставку через промежуточный узел;
2. неизвестного адресата;
3. прекращение пересылки по TTL;
4. подавление дубликатов по `messageId`;
5. некорректное сообщение и частичный приём;
6. недоступный сервер.
